  Integration кладёт стриминг-треки в общую БД — дампы медиатеки (artists/albums/titles 0 99999)
  их отдавали, нечёткий матч выбирал спотифай-артиста/альбом. Фикс — настройка LMS (Do not
  integrate, владелец 05.10) + wipecache 05.10 (обычный rescan НЕ чистит! итог: 68 треков, 0 призраков); код клиента НЕ меняли (решение владельца: поиск по БД
  как есть). SSH на бокс 192.168.1.131: root, пароль в банк не пишем — спросить у владельца.
- **Tasker-виджеты, отступ в начале строк** (05.10, фиксовано): %break задавалась многострочным
  литералом в prj.xml → значение содержало табы отступа файла. Правильно: `&#10;` (только перенос строки).
  При правке Tasker-экспортов руками проверять многострочные <Str> (`grep 've="3">$'`).
- **Пропал «шум» перед музыкой при просрочке** (05.10, исправлено): config.silence потерялся при
  миграции на плагин. Правка config.json клиента — только при ОСТАНОВЛЕННОМ сервисе (клиент
  сохраняет конфиг при завершении и затирает правки). Значение: loop://natural/rain_outside.mp3.

  (20:38, 20:40, ~23:07, ~23:10), две последние — БЕЗ следов (без стека/hs_err/OOM/System.exit),
