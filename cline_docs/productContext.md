# Product Context — зачем проект и откуда он

## Зачем
LMS — лучший домашний аудиосервер, но у Яндекса нет для него интеграции с УДЯ.
Проект закрывает это: колонки LMS становятся устройствами «музыка» в УДЯ,
плюс отдельный голосовой навык «Раз Два» для расширенных команд («что играет»,
«включи альбом …» через Spotify, выбор колонки в комнате и т.д.).

## Эволюция
- `squeeze-alice` — первый клиент (polling Яндекс API + MQTT в старых версиях).
- `squeeze-alice-cloud` (`org.knovash.alicebroker`) — первое облако-брокер (тогда с MQTT/Hive).
- `sa_server` — актуальное облако: HTTP + WebSocket, без MQTT.
- `sa_client` — актуальный клиент: переработка squeeze-alice + облачный транспорт.
  Прежнее имя плагина — SAClient (данные автоматически мигрируются в LyrionYandexBridge).

## Пользователи
Автор (knovash) + все, кто добавит репозиторий плагина в LMS. Публичный код:
https://github.com/knovash/lyrion-yandex-bridge (Issues/PR приветствуются).

**Проект МУЛЬТИПОЛЬЗОВАТЕЛЬСКИЙ по дизайну**: каждый ставит плагин, авторизуется в Яндексе
через облако (instanceToken → свой yandexUid), запросы маршрутизируются своему клиенту.
Посторонние запросы навыка — норма, белый список НЕ делать.
Первый «гость» уже заходил (02.10.2026: команды «test» и пустая, вреда нет).
Учёт пользователей — по числовому yandexUid в логах клиента и облака.
