0. ЧТО ЭТО И КАК УСТРОЕНО
--------------------------------------------------------------------------------

7 скриптов этапов + make_zip.sh + 5 папок payload_* с файлами для колонки.
Плюс lite-kit/ (стенд рута). Прошивка .46 (64 МБ) — ОТДЕЛЬНЫЙ файл в git:
в wizard-zip её НЕТ; перед рутом скачать (raw-URL или зеркало — см. Этап 1).

    stand.sh              — стенд lite-kit (DNS + HTTPS-сервер прошивки)
    root.sh               — минимальный рут: dropbear SSH + OTA-off + маркеры
    squeezelite.sh        — LMS-плеер squeezelite
    local_commands.sh     — commandslistener (экс-whatplays, голосовые фразы)
    bt_remote.sh          — BT-пульт (btrcv + btkeys, Entware через yse)
    airplay.sh            — AirPlay 2 (shairport-sync + nqptp + avahi)
    make_zip.sh           — пересобрать alice-root-wizard.zip (БЕЗ прошивки)
    save_to_payloads.sh   — ЗАПАСНОЙ dev-инструмент: подтянуть файлы с живой
                             станции в payload_* (обычно НЕ нужен — они полные)

Каждый этап изолирован:
  - stand.sh + root.sh  — обязательная пара (сначала стенд, потом рут)
  - squeezelite.sh, local_commands.sh, airplay.sh — независимы
  - каждый можно перезапускать отдельно

Инфраструктура:
  LMS + мост sa_client:  192.168.1.131 (LMS :9000, мост :8888)
  SSH-порт станции:      2222
  ADB-порт станции:      5555
  Прошивка для рута:     yandexmicro 0.369.1.46.4778262442.20261013.297
                           (ХРАНИТСЯ В GIT ОТДЕЛЬНЫМ ФАЙЛОМ — свой стабильный
                            raw-URL; в alice-root-wizard.zip НЕ входит, там
                            только скрипты+payload+lite-kit. Оба файла
                            обновляются пушем, НЕ привязаны к релизам)

3. ЭТАП 1 — РУТ: stand.sh + root.sh
--------------------------------------------------------------------------------

ТРЕБУЕТСЯ:
  - Ноутбук с Linux, sudo, интернет, в той же LAN
  - Роутер с доступом к настройкам DNS
  - Телефон с «Дом с Алисой» на LTE
  - Колонка Лайт 1 с прошивкой .46 (для рута)

--- ТЕРМИНАЛ 1: stand.sh ---

    cd ~/IdeaProjects/sa_client/alice-root-wizard
    ./stand.sh

Скрипт:
  1) поставит зависимости
  2) освободит :53 (dnsmasq), :80 и :443 (apache2 + старые python lite-kit)
  3) возьмёт lite-kit ЛОКАЛЬНО из alice-root-wizard/lite-kit/ (клон — только
     если папки нет; интернет для клона НЕ нужен)
  4) прошивка .46 — lite-kit/firmware/yandexmicro/ (ОТДЕЛЬНЫЙ файл в git;
     если пусто — скачать raw-URL'ом или ./lite-kit/install-firmware.sh):
       curl -L -o lite-kit/firmware/yandexmicro/0.369.1.46.4778262442.20261013.297.zip \
         https://raw.githubusercontent.com/knovash/lyrion-yandex-bridge/main/alice-root-wizard/lite-kit/firmware/yandexmicro/0.369.1.46.4778262442.20261013.297.zip
  5) напечатает IP ноутбука и инструкции
  6) запустит стенд в форграунде

--- РУКАМИ (пока стенд работает) ---

  1. Роутер: DNS 1 = <IP ноутбука из stand.sh>, DNS 2 = пусто.
     Если роутер требует непустой DNS 2 — вписать тот же IP.

  2. Сброс колонки:
     - выдернуть питание
     - вставить обратно
     - при появлении подсветки зажать ▶‖ 6-10 секунд
     - дождаться жёлто-зелёного кольца

  3. Привязка через «Дом с Алисой»:
     - телефон ОТКЛЮЧИТЬ от Wi-Fi (только LTE!)
     - приложение → «Добавить устройство»
     - дойти до экрана пароля Wi-Fi → ОСТАНОВИТЬСЯ (пароль не вводить)
     - ждать 30-60 секунд, колонка возьмёт оффер .46 со стенда

  IP колонки — в логе стенда (терминал 1) или в DHCP-таблице роутера.

  ПРОВЕРКА СТЕНДА (терминал 2):
    sudo ss -tulpn | grep -E ':(53|80|443) '   # :53 dnsmasq, :80/:443 python3
    dig @192.168.1.130 quasar.yandex.net +short   # должен вернуть .130
    curl -sk https://192.168.1.130/ -o /dev/null -w "HTTPS: %{http_code}\n"

--- ТЕРМИНАЛ 2: root.sh (после появления ADB) ---

    cd ~/IdeaProjects/sa_client/alice-root-wizard
    ./root.sh <IP_колонки>

Скрипт:
  1) защита от повторного запуска (если SSH уже работает → die)
  2) adb connect + ожидание ADB root (до 5 мин)
  3) remount rw
  4) dropbear + dropbearkey + S99zdropbear
  5) mkdir /data/opt/bin, /data/opt/etc/dropbear, /etc/dropbear
  6) OTA-off через yandex-noupdate.sh + постоянная копия в /data/opt/
  7) маркеры activate_* +i
  8) remount ro
  9) timeout 15 adb shell ... start dropbear (не блокируется)
 10) проверка SSH с ретраями (5 × 3с)

Ожидаемый результат в конце:
  [root] SSH работает
  ГОТОВО. Рут на <IP> есть.
  ВАЖНО: если yandex-noupdate.sh написал "Перезагрузи колонку" — сделайте adb reboot

--- ОБЯЗАТЕЛЬНО: ребут ---

    adb reboot
    sleep 90

    ssh -p 2222 root@<IP> "id; ps | grep [d]ropbear"
    # ожидаем uid=0(root) + dropbear БЕЗ ручного запуска

    ssh -p 2222 root@<IP> "ps | grep -E 'maind --updatesd' || echo 'updatesd НЕ работает (хорошо)'"
    # ожидаем "updatesd НЕ работает"

    ssh -p 2222 root@<IP> "sh /data/opt/yandex-noupdate.sh status"
    # ожидаем: launch.json: updatesd убран, applier: заглушён, ota key: подменён,
    # процессы апдейтера: maind --updatesd не запущен

--- ВЫКЛЮЧИТЬ СТЕНД ---

  Терминал 1: Ctrl+C
  Роутер: вернуть DNS как было

  Правильная остановка (не просто Ctrl+C):
    sudo pkill -9 -f 'lite-kit'
    sudo pkill -9 dnsmasq
    sudo ss -tulpn | grep -E ':(53|80|443) '   # должно быть пусто
    sudo systemctl start apache2   # если нужен

4. ЭТАП 2 — squeezelite.sh (LMS-плеер)
--------------------------------------------------------------------------------

    cd ~/IdeaProjects/sa_client/alice-root-wizard
    ./squeezelite.sh <IP_колонки>

Дефолт: LMS=<discovery>, NAME="Yandex Lite 2 SL"

Опции:
  --lms <HOST:PORT>    явно указать LMS (по умолчанию — discovery)
  --name "<NAME>"      имя плеера в LMS

ВАЖНО: по умолчанию -s НЕ добавляется. Squeezelite сам находит LMS
       через broadcast на :3483. Это проверено на .122 и .113.
       -s нужен только если LMS в другой подсети или broadcast блокируется.

ИМЯ ПЛЕЕРА:
  Должно совпадать с тем, что ждёт announce() в commandslistener.sh.
  На эталоне .115: [ "$RP" = "Yandex Lite 2 SL" ] && return
  Если задать своё имя — надо поправить commandslistener.sh (см. Этап 3).

Проверка:
  - в LMS http://192.168.1.131:9000 → плеер '<NAME>' должен появиться
  - через SSH: cat /proc/$(pidof squeezelite)/cmdline

ГРАБЛИ squeezelite на .113:
  - При ручном запуске из SSH: "test_open:281 playback open error: No such file
    or directory" — потому что нет export ALSA_CONFIG_PATH.
  - В S98squeeze ДОЛЖНА быть строка:
        export ALSA_CONFIG_PATH=/usr/share/alsa/alsa.conf
  - Если её нет — добавить, иначе плеер падает.

5. ЭТАП 3 — local_commands.sh (голосовые фразы, commandslistener)
--------------------------------------------------------------------------------

    cd ~/IdeaProjects/sa_client/alice-root-wizard
    ./local_commands.sh <IP_колонки> --room <Имя> --aliceid <UUID>

На колонке файл называется commandslistener.sh (экс-whatplays v5; на живых
станциях переименован 18.11, содержимое то же). Установщик гасит процессы
ОБОИХ имён — миграция без дублей. Лог: /tmp/whatplays.log (имя сохранено).

Параметры:
  --room <Имя>       ИМЯ комнаты (обязательно) — как в УДЯ, например «Душ»
  --aliceid <UUID>   UUID колонки (обязательно, см. раздел 15)
  --player "<Имя>"   имя LMS-плеера станции для announce() — то же, что --name
                     в squeezelite.sh. По умолчанию не меняется ("Yandex Lite 2 SL")
  --bridge <H:P>     адрес моста (по умолчанию 192.168.1.131:8888)
  --lms <H:P>        адрес LMS (по умолчанию 192.168.1.131:9000)

Что делает скрипт:
  1) ssh connect
  2) читает MAC wlan0 → SQP
  3) готовит commandslistener.sh локально (sed по LMS/SAC/ROOM/SQP/ALICEID + PLAYER при --player)
  4) проверяет синтаксис
  5) remount rw + push бинарников в /data/opt/bin/
  6) push S97cmdlistener в /etc/init.d/
  7) remount ro
  8) kill старых процессов + очистка /tmp
  9) ЗАПУСК whatplays через ДВОЙНОЙ setsid (SSH не блокируется)
 10) проверка отдельным SSH (процессы + лог)
 11) смоук whats_playing_text через мост

КЛЮЧЕВОЙ ПАТТЕРН запуска (busybox sh + SSH):

  busybox sh НЕ отвязывает stdin/stdout от SSH-пайпа при "setsid ... &".
  Рабочий паттерн — двойной setsid + </dev/null + exit 0:

    ssh host 'setsid sh -c "setsid <CMD>" </dev/null >/dev/null 2>&1 & sleep 1; exit 0'

  Без этого SSH висит после запуска whatplays.

Проверка после запуска:
  - процессы: супервизор (while :; do ... done), commandslistener.sh, maind --cli,
              alice_ipc_mon, subshell ({commandslistener.sh})
  - лог: === старт v5 === + CLI-сессия cancel: одиночная
  - смоук вернёт текст «сейчас играет/не играет ...»

ВАЖНО про announce():
  Если имя плеера (--name в squeezelite.sh) НЕ равно "Yandex Lite 2 SL",
  проще всего перезапустить local_commands.sh с --player "<то же имя>".
  Или поправить announce() в /data/opt/bin/commandslistener.sh вручную:

    ssh -p 2222 root@<IP> '
      mount -o remount,rw /
      sed -i "s#Yandex Lite 2 SL#<ИМЯ_ПЛЕЕРА>#g" /data/opt/bin/commandslistener.sh
      sh -n /data/opt/bin/commandslistener.sh
      sync; mount -o remount,ro /
      ps | grep -E "commandslis[t]ener\.sh|whatpl[a]ys\.sh" | awk "{print \$1}" | xargs -r kill -9 2>/dev/null || true
      sleep 2
      /etc/init.d/S97cmdlistener start   # или двойной setsid вручную
    '

  Без этого announce() не сработает → колонка будет говорить поверх своей музыки
  (или падать с onTtsPlayerError).

5а. ЭТАП 3а — bt_remote.sh (Bluetooth-пульт)
--------------------------------------------------------------------------------

    cd ~/IdeaProjects/sa_client/alice-root-wizard
    ./bt_remote.sh <IP_колонки> --player <Имя LMS-плеера> --room <Комната>

Пример (эталон Гостиная, пульт G20S → HomePod1):
    ./bt_remote.sh 192.168.1.115 --player HomePod1 --room Гостиная

Требуется:
  - рут (Этап 1) и SSH; интернет НА СТАНЦИИ (Entware ставится через yse)
  - bridge sa_client (по умолчанию 192.168.1.131:8888, --bridge <H:P>)

Что ставит:
  1) yse + Entware (bootstrap, если его нет) + bluez-daemon/libs/utils
  2) btrcv + btkeys-grab.sh + bt-connect.sh + bt-remove.sh
     + bt-listeners-start.sh + beep.wav (каждая заливка с SHA-сверкой)
  3) хранилище бондов /data/opt/bluetooth (+симлинк /var/lib/bluetooth)
  4) Entware D-Bus на /opt/var/run/dbus (вендорский НЕ трогается!)
  5) /data/opt/bt.conf: server <bridge> + default <player> <room>
     (смена bridge-сервера = правка ОДНОЙ строки server в bt.conf)
  6) S99btkeys в /etc/init.d — автозапуск стека при загрузке (~25с)

Подключение пульта:
  ssh -p 2222 root@<IP>  →  /data/opt/bin/bt-connect.sh
  → зажать комбо паринга на пульте (LED мигает):
     G20S PRO: OK+Return 3-5с; ATV3: Back+Home; Xiaomi RC: Home+Menu; BPR2S: OK+Vol-
  → три бипа = подключено; слушатель сам поднимется и попадёт в bt.conf

Кнопки (btkeys-grab.sh): ◀▶=треки, OK=play/pause, VOL±, Home=switch_here,
  Search=«что играет», 1-9=избранное. Бип на каждое нажатие; ошибки /cmd —
  в /tmp/btkeys.log («✗ … подряд: N»), после 3 подряд двойной бип;
  heartbeat слушателей — /tmp/bt.status.<uniq>.

ГРАБЛИ (полный журнал — lite-bt.md в корне sa_client):
  - вендорское ядро 4.9 отдаёт input-события ТОЛЬКО через EVIOCGRAB — btrcv
    делает это сам; dd/cat на event-узел ничего не дадут (это норма);
  - directed advertising: пульт «виден» только в момент нажатия кнопки;
  - bt-listeners-start v3 НЕ трогает вендорский D-Bus/bluealsa/maind (Алиса жива).

8. ЭТАП 6 — ГОЛОСОВОЙ ТЕСТ
--------------------------------------------------------------------------------

На колонке произнести:

  «Алиса, дальше»           — переключение трека/канала
  «Алиса, назад»            — предыдущий
  «Алиса, повтор»           — тумблер повтора
  «Алиса, рандом»           — тумблер шафла
  «Алиса, отдельно»         — разгруппировать
  «Алиса, вместе»           — сгруппировать
  «Алиса, что играет»       — озвучка текущего трека
  «Алиса, спотифай <X>»     — включить исполнителя
  «Алиса, избранное <X>»    — закладка LMS

Параллельно на колонке:

    ssh -p 2222 root@<IP>
    tail -f /tmp/whatplays.log

Для «дальше» ожидаемое в логе:
    ФРАЗА: альше · текст: Дальше
    → cancel (мгновенный)
    → next (трек/канал, room=<Имя>)

Если ФРАЗА есть, а next нет — проблема с мостом.
Если ФРАЗА нет — проблема с alice_ipc_mon (IPC не читается).

10. ТИПИЧНЫЕ ОШИБКИ И РЕШЕНИЯ
--------------------------------------------------------------------------------

А. ADB без root (uid=2000)
   Причина: прошивка не .46 или оффер не пришёл.
   Решение: повторить сброс, привязку (телефон на LTE!), проверить DNS.

Б. adb: device offline
   Причина: колонка не в сети / другой IP / сброс не завершён.
   Решение: ping <IP>, adb disconnect && adb connect <IP>:5555.

В. stand.sh: "Address already in use" на :53 / :80 / :443
   Причина: apache2 на :80, старый python lite-kit на :443, системный dnsmasq.
   Решение: исправленный stand.sh уже освобождает эти порты.
            Если повторилось — вручную:
              sudo systemctl stop apache2 dnsmasq
              sudo pkill -9 apache2 dnsmasq
              sudo ss -tulpn | grep -E ':(80|443|53) '   # должно быть пусто

Г. SSH молчит после ребута
   Решение:
     adb shell "cat /data/opt/etc/dropbear/dropbear.log"
     adb shell "ls -la /data/opt/etc/dropbear/"
     adb shell "/etc/init.d/S99zdropbear start"

Д. root.sh зависает на "Старт dropbear"
   Причина: adb shell не возвращает управление, dropbear держит пайп.
   Решение: Ctrl+C, adb shell "ps | grep dropbear" — процесс обычно работает.
            Исправленный root.sh использует timeout 15.

Е. local_commands.sh зависает на "Рестарт commandslistener"
   Причина: setsid ... & через SSH не отвязывает stdin/stdout.
   Решение: исправленный local_commands.sh использует двойной setsid:
              setsid sh -c "setsid ..." </dev/null >/dev/null 2>&1 & sleep 1; exit 0
            Если повторилось — запустить вручную:
              ssh -p 2222 root@<IP> 'setsid sh -c "setsid /bin/sh -c \"while :; do /data/opt/bin/commandslistener.sh >> /tmp/commandslistener.err 2>&1; sleep 3; done\"" </dev/null >/dev/null 2>&1 & sleep 1; exit 0'

Ж. commandslistener не запускается, файла /tmp/whatplays.log нет
   Причина: процесс ни разу не стартовал.
   Решение: проверить err-лог: cat /tmp/commandslistener.err
            запустить вручную в форграунде через SSH, чтобы увидеть ошибку:
              ssh -p 2222 root@<IP> '/data/opt/bin/commandslistener.sh'

З. «maind --updatesd РАБОТАЕТ» в status
   Причина: launch.json обновлён, но процесс уже в памяти.
   Решение: adb reboot — после ребута updatesd не запустится.

И. squeezelite: "unable to open output device: default"
   Причина: нет export ALSA_CONFIG_PATH=/usr/share/alsa/alsa.conf
   Решение: добавить в /etc/init.d/S98squeeze перед start():
              export ALSA_CONFIG_PATH=/usr/share/alsa/alsa.conf

К. «что играет» говорит поверх музыки / onTtsPlayerError
   Причина: имя плеера не совпадает с announce() в commandslistener.sh.
   Решение: sed -i "s#Yandex Lite 2 SL#<ИМЯ>#g" /data/opt/bin/commandslistener.sh
            (и рестарт whatplays).

14. СПРАВКА ПО ФРАЗАМ whatplays
--------------------------------------------------------------------------------

Голосовые фразы, которые ловит commandslistener.sh:

    дальше                  → next (трек или канал)
    назад                   → prev
    повтор                  → repeat_on / repeat_off (тумблер)
    рандом                  → shuffle_on / shuffle_off (тумблер)
    отдельно                → separate_on
    вместе                  → separate_off
    переключи сюда          → switch_here
    переключи музыку в/на X → switch_room
    что играет              → whats_playing_text (голосом)
    спотифай X              → spotify_artist
    спотифай X альбом Y     → spotify_album
    спотифай трек X         → spotify_track
    спотифай плейлист X     → spotify_playlist
    избранное X             → favorite_name

Триггеры в коде:
  PATTERNS='альше азад овтор андом тдельно месте ереключи грает'
  SPOPAT='потифай otify збранное'

Шаблоны БЕЗ первой буквы (регистронезависимость): ASR выдаёт «Дальше»,
«Что играет» с заглавной, а glob в shell чувствителен к регистру.

15. ПОЛУЧЕНИЕ ALICEID ЧЕРЕЗ API УДЯ
--------------------------------------------------------------------------------

ALICEID (UUID для voice_say) — берётся ТОЛЬКО через API УДЯ.
НЕ путать с серийником (LY0000…:NNNNNNNNN) — это другое поле!

Способ (нужен OAuth-токен с правом iot:view):

    curl -s -H "Authorization: Bearer <OAuth-токен>" \
      "https://api.iot.yandex.net/v1.0/user/info" \
      | jq '.devices[] | select(.quasar_info.device_id == "<серийник>") | {id, name, room}'

Где:
  - <серийник> — ищем по полю quasar_info.device_id
  - "id"       — ЭТО UUID для --aliceid
  - "room"     — комната УДЯ (для --room)

Пример для Яндекс Лайт Душ (.113):
  серийник = LY000000000000120306000081b1bc4b
  UUID     = ede2e7e9-f002-43f4-8c7e-aa29274b3e4b
  room     = Душ

Альтернативы (менее надёжные):
  - https://iot.quasar.yandex.ru/m/v3/user/devices — отдаёт тот же JSON,
    но структура внутренняя и может измениться.
  - yandex.ru/iot → устройство → quasar_device_id (не всегда виден).

Если сценария "SA voice <UUID>" в УДЯ НЕТ — voice_say уйдёт в fallback на Piper:
  - Создать: yandex.ru/iot → Сценарии → "SA voice <UUID>"
  - Триггер: редкая фраза (например «пустышка»)
  - Действие: <станция> → Скажи «пустышка» (текст не важен)

Проверка:
  wget -qO- "http://192.168.1.131:8888/cmd?action=voice_say&alice=<UUID>&value=%D1%82%D0%B5%D1%81%D1%82"
  # ALICE ok — сценарий есть, голос Алисы через voice_say работает
  # PIPER <url> — fallback на Piper (голос локальный)
  # ошибка — ни сценария, ни Piper
